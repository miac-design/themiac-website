# Project documentation template

## Project overview
- Title, organization, dates, status
- Business or user question
- My role, authority, collaborators
- Short executive summary

## Scope and deliverables
List each artifact, date, ownership and public link where permitted.

## Process and decisions
Document methods, inputs, key choices, alternatives and rationale. Distinguish personal contributions from team work.

## Outcomes and impact
For each claim: metric or observation, source, date, baseline, attribution and limitation. Mark proposed outcomes as proposed. Never infer a measured improvement from implementation alone.

## Evidence register
Source ID or URL, source date, claim supported, confidentiality, permission to publish. Private emails and internal files stay private; public summaries do not expose them.

## Detailed report
Executive summary, problem, approach, findings, recommendations or implementation, impact, limitations, next steps. Use concise, specific writing. No em dashes or invented metrics.

## Publication checklist
Confirm role and dates, validate links, check confidentiality, verify claims, review desktop and mobile layout. Save a dated project record before publishing. Do not publish future projects automatically without an authorized publishing workflow.
